**未解決の構造課題**（2026-09-05に特定）。

ショートウッド部門の20キーはすべて「◯◯ 7W/9W」で、**7Wと9Wを1つの中央値にまとめている**。
ところが値段が違う。

```
ELYTE 実測（120日・完品・無印のみ）
  7W  n=21  中央 32,000
  9W  n=12  中央 38,600   ← 9Wは7Wの 1.21倍
```

9/5に6日ぶりの割安圏が出たが偽物だった。

```
レポート: ELYTE 7W/9W 完品n=4・中央40,850 → 販売中29,999が「73%の割安圏」
実際    : 30日窓の4本のうち2本が9W（37,700／45,000）で中央が上振れ。
          候補は7W なので 7W実勢32,000 の **94%**。粗利+301・倍率1.07倍で見送り
```

**Why:** CLAUDE.md には「**9Wは高いが回転が遅いので集めるのは7Wに絞る**」と書いてあり、
値段が違うことは分かっている。それなのにキーが1つなので、
**9Wが混ざった日は必ず中央値が上振れし、7Wの玉が割安に見える**。

`MIN_N_FOR_RATIO=3`（9/1導入）は「n<3」の穴を塞いだが、
**番手混在は別の入口**なので素通りする。

**How to apply（当面の運用）:**
- **ショートウッドの割安圏に出た玉は、まず番手（7Wか9Wか）を確認する**
- そのうえで**同じ番手だけで120日の中央値を測り直してから**判断する
- 部門テーブルの中央値は「7W/9Wの混合値」だと意識して読む

**直し方の候補（未実施）:**
1. `shortwood_report` で中央値と割安率を**番手別に出す**（キーは触らない・軽い）
2. カタログを `sw_◯◯_7w` / `sw_◯◯_9w` に分割（20キー→40キー・重い）
→ まず1を試すのが現実的。9Wは玉が薄い機種が多く、分割するとn<3が量産される。
