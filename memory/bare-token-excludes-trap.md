**Why:** クラブ名の修飾語（X / TOUR / MAX / ◆◆◆）は、**シャフト名にも同じ語が使われる**。
短いトークンほど衝突する。
**さらに `normalize()` は空白を保持する**ので、"elytex" のような続き書きのパターンは
「ELYTE X」のようなスペース入り表記を取りこぼす。さらに記号は表記ゆれが激しく、
`♦`(U+2666) と `◆`(U+25C6) は**別の文字**で、`♦︎♦︎♦︎` は異体字セレクタが挟まるので
`♦♦♦` では拾えず **単体の `♦`** でしか拾えない。

**How to apply:**
1. excludes / required に書くのは**型名の形**にする。
   例: `"x"` → `"paradymx|パラダイムx"`、`"tour|ツアー"` → `"qi35 tour|qi35 ツアー|qi35tour"`
   （`normalize()` は**空白を保持する**ので、隣接語で絞れる）
2. 記号は**表記ゆれを列挙**して定数化する。例: `_PARADYM_TD = "◆◆◆|♦|トリプルダイヤ|triplediamond"`
3. **除外と受け皿の required は必ずセットで直す**。片方だけだと「落とすだけで行き先が無い」状態になる
4. 直す前に**実際のタイトルで新旧パターンを突き合わせる**（落とすべき/残すべきを並べて表示）。
   3件とも、この突き合わせで誤検出が事前に見えた
